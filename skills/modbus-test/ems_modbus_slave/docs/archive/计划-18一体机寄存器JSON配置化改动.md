# 18 一体机寄存器 JSON 配置化模拟器改动计划

## 1. 改动目标

将 `DM-HPWT18-U1/Modbus Protocols` 中的 Modbus CSV 协议表转换为机器可读的设备 JSON 配置。模拟器启动后扫描配置目录，用户在“模拟从站”下拉框选择设备时，程序自动加载对应 JSON、初始化寄存器/线圈、切换串口默认参数，并按配置提供 Modbus RTU 从站响应。

首期只实现 `DM-HPWT18-U1（18 一体机）`，但配置结构和加载流程需允许后续新增设备时仅增加 JSON，不修改设备列表代码。

## 2. 已确认的协议事实

- 通讯接口：Modbus RTU、RS485、`9600 bit/s`、`8N1`。
- 从站地址范围：空调设备 `1~40`。
- 保持寄存器功能码：`FC03 / FC06 / FC10`。
- 线圈功能码：`FC01 / FC05 / FC0F`。
- 只读保持寄存器从 `word 300` 开始，可读写保持寄存器从 `word 0` 开始。
- 只读线圈从 `bit 8000` 开始，并映射到 `word 500` 起的位域。
- 可读写线圈从 `bit 6400` 开始，并映射到 `word 400` 起的位域。
- 同一线圈既可能通过线圈功能码访问，也可能通过对应 word 寄存器功能码访问，两种访问必须共享底层数据。
- CSV 使用两行/三行组合表头、换行枚举、空白继承单元格和 `word 4（YD）` 等非纯数字地址，不能直接使用普通单行 `DictReader` 原样转换。

## 3. 本期范围

### 3.1 包含

- CSV 协议提取工具。
- 统一设备 JSON Schema。
- 18 一体机完整寄存器、线圈配置 JSON。
- JSON 格式及业务约束校验。
- 运行时自动发现设备配置。
- UI 选择设备并导入配置。
- 保持寄存器和线圈的统一数据模型。
- 实现 `FC01 / FC03 / FC05 / FC06 / FC0F / FC10`。
- 配置加载失败时的明确错误提示。
- 配置切换、寄存器读写、线圈读写和位域同步测试。

### 3.2 暂不包含

- 温度自动变化、压缩机启停时序等动态业务状态机。
- 通讯超时、CRC 错误、延迟响应等异常注入。
- 用户在 UI 中编辑 JSON Schema 或重新生成 JSON。
- 同时启动多个不同设备实例。

本期先实现“协议数据驱动的准确模拟”。动态逻辑后续通过 JSON 中的 `logic_plugin` 接口接入。

## 5. JSON 配置设计

### 5.1 顶层结构

```json
{
  "schema_version": 1,
  "device": {
    "id": "dm_hpwt18_u1",
    "name": "DM-HPWT18-U1（18一体机）",
    "description": "主控板-热泵 Modbus 从站模拟",
    "protocol_version": "2024-02-01",
    "logic_plugin": null
  },
  "serial": {
    "baudrate": 9600,
    "data_bits": 8,
    "parity": "N",
    "stop_bits": 1,
    "default_slave_id": 1,
    "slave_id_min": 1,
    "slave_id_max": 40,
    "response_delay_ms": 6
  },
  "function_codes": [1, 3, 5, 6, 15, 16],
  "holding_registers": [],
  "coils": [],
  "ui": {
    "status_fields": []
  },
  "source": {
    "directory": "DM-HPWT18-U1/Modbus Protocols",
    "generated_at": "",
    "files": []
  }
}
```

### 5.2 保持寄存器项目

```json
{
  "address": 4,
  "address_label": "word 4（YD）",
  "name": "设定开关机",
  "key": "power_command",
  "access": "rw",
  "data_type": "s16",
  "default_raw": 85,
  "minimum_raw": null,
  "maximum_raw": null,
  "scale": 1,
  "unit": null,
  "enum": {
    "85": "关机",
    "170": "开机"
  },
  "description": "",
  "reserved": false,
  "source_table": "寄存器（可读写）"
}
```

约定：运行时统一保存 `raw` 原始 16 位值；`scale`、`unit` 和 `enum` 只用于合法性校验及 UI 显示。十六进制默认值和枚举键在 JSON 中转换成十进制数字，原始文字保留在 `address_label` 或 `description` 便于追溯。

### 5.3 线圈项目

```json
{
  "address": 6400,
  "name": "超强",
  "key": "turbo_mode",
  "access": "rw",
  "default": false,
  "false_label": "关闭",
  "true_label": "开启",
  "backing_register": 400,
  "bit_offset": 0,
  "ui_level": "用户级",
  "description": "不记忆",
  "reserved": false,
  "source_table": "线圈（可读写）"
}
```

`backing_register` 和 `bit_offset` 是线圈与 word 位域同步的唯一依据。例如 `bit 6400` 对应 `word 400` 的 bit0，`bit 6415` 对应 `word 400` 的 bit15。

### 5.4 JSON 必须满足的校验规则

- `device.id` 在 profiles 目录内唯一。
- 保持寄存器地址唯一，线圈地址唯一。
- 地址均在 `0~65535`，从站地址在 `1~247` 且默认值落在设备范围内。
- `access` 只能为 `r` 或 `rw`。
- `default_raw` 必须满足数据类型、范围和枚举约束。
- 每个线圈的 `backing_register` 必须存在。
- `bit_offset` 必须为 `0~15`，同一 backing word 内不得重复。
- `FC05/FC0F` 只允许写 `rw` 线圈；`FC06/FC10` 写入包含只读位的 word 时，采用第 8.3 节的规则。
- `key` 可选；存在时必须唯一，并采用稳定英文 snake_case，不能由中文名称临时拼音化生成。

## 6. CSV 提取工具计划

### 6.1 输入

固定读取以下文件：

- `协议说明.csv`
- `寄存器（只读）.csv`
- `寄存器（可读写）.csv`
- `线圈（只读）.csv`
- `线圈 （可读写）.csv`
- `更改记录.csv` 仅记录来源，不生成点位。

### 6.2 提取流程

1. 使用 Python 标准库 `csv` 以 UTF-8 读取，保留包含换行的单元格。
2. 跳过功能码说明行，按每张表的实际组合表头映射固定列。
3. 对 `word/byte/bit` 地址提取数字，保留原始地址文本。
4. 对线圈表中的空白 word/byte 单元格执行向下填充。
5. 将 `R`、`R/W` 规范化为 `r`、`rw`。
6. 将 `/`、空字符串规范化为 `null`，但不丢弃原始备注。
7. 解析十进制和 `0x` 十六进制默认值/枚举值。
8. 从“传输值=实际值*10”等描述提取比例；无法可靠解析时保留原文并输出 warning，不猜测。
9. 根据线圈地址及 word 地址计算 `bit_offset`，并验证地址关系。
10. 预留项也写入 JSON，以保证连续地址读请求能够正确响应；UI 默认隐藏预留项。
11. 生成 JSON 后执行 Schema、地址唯一性、默认值和位域一致性校验。
12. 输出转换摘要：各类点位数量、警告数量、无法解析行及源文件行号。

### 6.3 命令接口

```powershell
python .\tools\extract_modbus_csv.py `
  --input "..\DM-HPWT18-U1\Modbus Protocols" `
  --output ".\profiles\dm_hpwt18_u1.json" `
  --device-id "dm_hpwt18_u1"
```

默认不覆盖已有 JSON；必须增加 `--force` 才能覆盖。生成采用确定性排序和格式，便于 Git 对比协议变化。

## 8. 关键运行逻辑

### 8.1 设备发现与选择

1. 程序启动时扫描 `profiles/*.json`。
2. 每个合法配置加入“模拟从站”下拉框，显示 `device.name`，内部保存 `device.id` 和路径。
3. 坏配置不使程序崩溃，在日志中显示文件名和错误原因。
4. 选择设备后加载完整 JSON，初始化数据区、表格、状态字段、波特率和从站地址。
5. 串口运行期间禁止切换设备；停止后才能切换。
6. 如果 profiles 中没有合法设备，禁用 Start 并提示配置目录。

### 8.2 保持寄存器与线圈同步

底层以 16 位 word 为主存储：

- 通过 FC05/FC0F 写线圈时，只修改 backing word 对应 bit。
- 通过 FC06/FC10 写 backing word 时，线圈读取立即反映对应 bit。
- UI 修改线圈或 word 时走同一数据存储接口。
- 批量写入先完整校验所有地址和值，全部合法才一次提交；任一项失败时不允许部分写入。

### 8.3 线圈 backing word 的写权限

协议允许线圈通过 FC06/FC10 写 word，但同一 word 可能包含不同权限位。第一版采用以下明确规则：

- 可读写线圈区 `word 400...`：允许通过 FC06/FC10 写入，配置为只读的 bit 保留原值。
- 只读线圈区 `word 500...`：拒绝 FC06/FC10 写入并返回 `0x02 Illegal Data Address`。
- FC05/FC0F 写只读线圈：返回 `0x02 Illegal Data Address`。
- 对协议中存在歧义的混合权限 word，在提取报告中列出并进行人工确认。

### 8.4 连续地址读取

当前程序遇到未定义地址即返回异常。新配置必须保留协议表中的预留地址/位，确保协议定义范围内的连续读取不被人为打断。超出配置范围或跨越真正空洞时返回 `0x02`。

### 8.5 UI 展示

- 设备下拉框由配置目录自动生成。
- 状态面板由 `ui.status_fields` 动态生成，不再写死寄存器地址。
- 点位表提供“全部 / 保持寄存器 / 线圈 / 仅可写 / 隐藏预留”筛选。
- 数值同时支持原始值和解释值，例如 `170 (开机)`、`250 (25.0 ℃)`。
- 写入失败时不静默 clamp；显示范围或枚举错误。协议模拟必须暴露非法值，而不是自动改成邻近合法值。

## 12. 风险与待确认项

### 12.1 协议数据清洗风险

CSV 中存在组合表头、自由文本枚举、`/`、跨行内容和空白继承。提取器应对可确定字段自动转换，对不确定内容保留原文并生成报告，不能静默猜值。

### 12.2 s16 与 Modbus 原始值

Modbus 线上始终传输 16 位无符号字。JSON 存储 `data_type=s16` 时，数据层仍保存 `0~65535` raw；UI 根据 s16 转成 `-32768~32767` 显示，避免负温度编码错误。

### 12.3 寄存器范围校验语义

协议中的最小/最大通常是“实际值”，JSON 需要转换成 `minimum_raw/maximum_raw` 后再校验。若比例字段无法可靠解析，本期只展示原文，不启用错误的范围限制。

### 12.4 写 word 时的只读 bit

第 8.3 节暂定对可写 word 中的只读 bit 采用“保留原值”。实施前应通过真实设备或协议负责人确认；如果设备实际行为是整 word 接受或整 word 拒绝，只需调整数据存储策略和测试期望。

### 12.5 广播地址 0

当前 UI 限制从站地址 `1~247`。是否支持 Modbus 广播写入地址 0 需要抓包或 GD32 行为确认；首版建议不响应地址 0，后续按实际联调需求增加“接受广播写、无响应”。

## 13. 推荐实施顺序

按“Schema/提取器 -> 数据存储 -> 六个功能码 -> 动态 UI -> 串口联调”推进。第一阶段完成后先提交生成的 JSON 和提取报告供人工抽查，再进入模拟器代码改造，可最早发现协议字段解释错误，减少后续返工。
