# PC网页经ESP32模拟18一体机测试计划

## 1. 背景

当前需要在不依赖真实 18 一体机整机的前提下，使用电脑侧网页作为测试入口，经由 ESP32 向 GD32 下发命令，并在测试过程中尽量模拟 18 一体机对 GD32 的控制与联动行为，用于验证通信链路、寄存器交互、功能动作和异常处理是否符合预期。

本计划优先服务于联调和功能验证，目标是先形成一套可执行、可复现、可扩展为自动化的测试流程。

## 2. 测试目标

1. 验证 `PC网页 -> ESP32 -> GD32` 控制链路可稳定工作。
2. 验证 PC 侧可替代 18 一体机完成核心控制命令下发。
3. 验证 GD32 接收命令后的寄存器状态、运行状态和控制输出符合预期。
4. 验证异常输入、通信中断、重复下发等场景下系统行为可控。
5. 为后续沉淀自动化测试脚本和回归测试集提供基础。

## 3. 测试范围

### 3.1 本次测试范围

- 关键控制命令的正确执行
- 关键状态寄存器的读回校验
- 基础异常场景处理
- 测试日志、结果记录、问题回归

### 3.2 暂不纳入本轮范围

- 真实 18 一体机 UI 外观和交互体验验证
- 所有外部表计、热源、水表、流量计的全量联调
- 云端完整业务链路验证
- 长周期老化测试

## 4. 测试架构

```text
PC浏览器/测试网页
    ->
ESP32 网关/转发层
    ->
GD32 被测控制器
    ->
寄存器状态 / 运行逻辑 / 输出动作
```

### 4.1 角色定义

- `PC网页`：测试操作入口，用于发送模拟 18 一体机命令、查看返回结果、记录测试日志。
- `ESP32`：协议桥接和命令转发节点。
- `GD32`：被测对象，负责执行控制逻辑、更新寄存器和驱动物理动作。

### 4.2 核心思路

PC 网页不需要完全复刻 18 一体机所有页面，而是优先模拟其“控制能力”：

- 下发开关机
- 下发模式切换
- 下发目标温度
- 下发参数写入
- 读取状态寄存器
- 读取故障/运行状态

也就是说，第一阶段先模拟“协议和功能行为”，而不是模拟“整套界面”。

## 5. 前提与依赖

## 5.1 硬件前提

- 1 台可运行网页和调试工具的 PC
- 1 块 ESP32 板卡，已烧录可与 GD32 通信的固件
- 1 块 GD32 被测板，版本固定
- 必要供电、电源、串口线、RS485 或 UART 连接线

## 5.2 软件前提

- 可访问的本地网页测试页面或调试页面
- ESP32 与 GD32 之间现有通信固件可正常运行
- 已知关键寄存器表、命令字典或控制映射关系
- 可查看串口日志、ESP32 日志或 GD32 调试日志

## 5.3 输入资料

- GD32 通信架构资料
- ESP32 与 GD32 通信协议说明
- 18 一体机涉及的关键控制项说明
- 寄存器定义表
- 当前测试固件版本号

## 6. 测试策略

采用“由浅到深”的四阶段策略，先打通链路，再验证功能，最后补异常与回归。

### 6.1 阶段一：链路打通

目标：

- 验证网页可以成功触发 ESP32 下发命令
- 验证 ESP32 可以将命令正确转发给 GD32
- 验证 GD32 可以返回可识别结果

重点测试项：

- 网页与 ESP32 连接建立
- 单条命令下发成功
- GD32 收到命令并返回结果
- 命令超时、空响应、重复点击处理

通过标准：

- 至少 5 个不同命令可稳定收发
- 单条命令成功率达到 100%
- 无随机丢包、无明显卡死

### 6.2 阶段二：核心功能验证

目标：

- 验证 PC 网页可替代 18 一体机完成核心控制动作

重点测试项：

- 开关机
- 模式切换
- 目标值设置
- 参数写入与读取
- 状态刷新
- 故障状态读取

通过标准：

- 页面下发值与 GD32 实际寄存器值一致
- GD32 动作与设计一致
- 不出现写入成功但状态未变化的情况

### 6.3 阶段三：异常与边界验证

目标：

- 验证系统在异常输入和异常链路场景下行为可控

重点测试项：

- 非法参数
- 超范围参数
- 连续快速重复下发
- ESP32 断连重连
- GD32 重启后状态恢复
- 命令执行中再次下发新命令

通过标准：

- 异常可被识别
- 系统不死机、不跑飞
- 恢复后可继续正常测试

### 6.4 阶段四：回归与固化

目标：

- 将高频稳定用例沉淀为固定流程

重点输出：

- 冒烟测试清单
- 回归测试清单
- 问题复现步骤模板
- 自动化脚本候选列表

## 7. 测试执行流程

## 7.1 准备阶段

1. 确认 ESP32 固件版本、GD32 固件版本。
2. 确认网页测试入口可用。
3. 确认 ESP32 与 GD32 接线正确。
4. 确认供电正常，串口或日志接口可查看。
5. 准备关键寄存器映射表和测试记录表。

## 7.2 冒烟阶段

1. 打开网页。
2. 建立与 ESP32 的连接。
3. 下发 1 条简单读取命令。
4. 下发 1 条简单写入命令。
5. 确认 GD32 返回和寄存器变化正确。

如果冒烟失败，暂停进入功能测试，先定位链路问题。

## 7.3 功能阶段

按功能域逐项执行：

1. 开关机类
2. 模式类
3. 目标值类
4. 参数配置类
5. 状态读取类
6. 故障状态类

每一项均需记录：

- 输入命令
- ESP32 转发结果
- GD32 返回值
- 寄存器变化
- 实际动作或现象
- 是否通过

## 7.4 异常阶段

1. 下发非法值
2. 下发边界值
3. 重复快速点击同一命令
4. 人为断开 ESP32 通信
5. 重启 GD32 再次读取状态
6. 验证恢复后能否继续下发命令

## 7.5 收尾阶段

1. 汇总通过项、失败项、阻塞项。
2. 归档截图、日志、串口记录。
3. 输出缺陷列表和复现步骤。
4. 更新下一轮回归清单。

## 8. 建议的测试项清单

### 8.1 链路类

- 页面连接 ESP32
- 页面断开再重连
- 命令发送超时提示
- 返回报文显示正确

### 8.2 控制类

- 开机
- 关机
- 模式切换
- 目标温度设置
- 配置参数下发
- 批量参数下发

### 8.3 状态类

- 运行状态读取
- 当前模式读取
- 目标值读取
- 温度类状态读取
- 压力类状态读取
- 故障码读取

### 8.4 异常类

- 非法寄存器地址
- 非法枚举值

### 8.5 恢复类

- ESP32 重连后恢复
- GD32 重启后恢复
- 页面刷新后重新测试

## 9. 页面能力建议

为了让网页更适合承担“18 一体机模拟端”的角色，建议页面至少提供以下能力：

- 连接/断开 ESP32
- 命令按钮区
- 参数输入区
- 当前状态展示区
- 请求/响应日志区
- 一键读取关键状态
- 一键执行冒烟测试
- 一键导出测试日志

若资源允许，后续可增加：

- 场景脚本执行
- 指令录制与回放
- 常用测试模板
- 异常注入开关

## 11. 角色分工建议

- `测试执行`：按计划操作网页、记录结果、回归问题。
- `ESP32负责人`：处理网页到 ESP32 的连接、转发和协议问题。
- `GD32负责人`：处理寄存器、动作逻辑、异常处理问题。
- `联调负责人`：统一判定问题归属，推进问题闭环。

## 12. 准入与准出标准

## 12.1 准入标准

- ESP32 固件可稳定运行
- GD32 固件已固定版本
- 网页入口可使用
- 关键寄存器表可查
- 基础接线完成并自检通过

## 12.2 准出标准

- 链路类冒烟测试全部通过
- 核心功能测试通过率达到预期
- 阻塞性问题已识别并记录
- 输出测试结论和遗留风险

## 13. 风险与注意事项

- 若 18 一体机真实协议细节尚未完全明确，网页模拟能力可能只能覆盖核心控制子集。
- 若 ESP32 仅做透明转发，则问题定位需要区分网页层、ESP32 层和 GD32 层。
- 若部分功能依赖外部传感器或外设输入，需要补充桩数据或专门的模拟机制。
- 若寄存器定义仍在变化，测试用例应绑定明确版本。

## 14. 下一步建议

建议按以下顺序推进：

1. 先确认网页要模拟的“最小 18 一体机功能集合”。
2. 先完成 5 到 10 条冒烟命令。
3. 再形成第一版测试用例表。
4. 跑通一次人工联调。
5. 最后把稳定流程沉淀成自动化脚本或固定操作模板。

## 15. 当前假设

本计划基于以下假设编写：

- PC 网页已经具备或即将具备向 ESP32 发命令的能力。
- ESP32 已具备向 GD32 转发命令的能力。
- 当前首要目标是验证功能链路，不是完整复刻真实 18 一体机前端。
- 测试计划暂以流程设计为主，具体寄存器地址和功能点清单后续可再细化。
